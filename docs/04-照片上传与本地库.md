# 04 · 照片上传与本地库

> 目标：摄影师把相机导出的 JPG（单张 5–20MB）拖进来，浏览器自动压到能长期保存、能快速加载的大小，并且同名文件不会互相覆盖。

## 1. 上传链路

```
选择/拖入文件 → 逐张压缩（canvas）→ 判断同名 → 写入 IndexedDB → 刷新网格
```

### 1.1 压缩策略

```js
if (/\.jpe?g$/i.test(file.name) && file.size <= 900 * 1024 && 长边 <= 1600) return file; // 已合规，直接复用
const scale = Math.min(1, 1600 / Math.max(bitmap.width, bitmap.height));
// 逐级降级：scale 不变时先降质量 0.85 → 0.72 → 0.6 → 0.48 → 0.36
// 仍超过 900KB 就把尺寸再乘 0.8，最多 4 轮
```

为什么是 1600px / 900KB：

- 手机看大图足够清晰，网格缩略图更快
- 单张 ≤900KB，几十张才几十 MB，IndexedDB 配额完全够
- 服务端快照上限 1MB，压缩后天然满足，不用二次处理

为什么用 `canvas.toBlob("image/jpeg", q)` 而不是 base64：Blob 可直接进 IndexedDB、可直接作为 `fetch` body，省一次编解码。

### 1.2 文件名规范化

```js
const stem = file.name.replace(/\.[^.]+$/, "");   // 去掉原扩展名
const key  = session + "/" + stem + ".jpg";        // 统一存 JPG
```

- PNG 也转 JPG：预览图不需要透明通道，体积更小
- **key 不带相机原始扩展名**，下游"导出文件名"与网盘 RAW 按主名匹配时更稳
- RAW（.ARW/.CR2/.CR3/.NEF/.RAF/.DNG/.ORF/.RW2）直接拒绝并提示"先导出 JPG"

### 1.3 同名检测

上传前先取该场次已有的 key 集合：

```js
const original = new Set(existingKeys);
const matches = files.filter(f => original.has(session + "/" + stem(f.name) + ".jpg"));
if (matches.length) action = await chooseDuplicateAction(matches); // skip / overwrite / cancel
```

选择"覆盖"时请求带 `overwrite=1`；选择"跳过"时直接计入 skipped。**本次批次内部重复的文件只上传一次**：用 `byKey` Promise 表让后一个等前一个结果。

### 1.4 并发与内存

- 压缩串行（一次解码一张原图，避免大图把内存打满）
- 传输并行最多 4 张
- 进度实时回写状态栏：`上传中 12/58 · 新增 10 · 覆盖 1 · 跳过 1 · 失败 0`
- 单张失败不中断整批，最后弹"部分照片未上传"报告，列出文件名与原因

## 2. IndexedDB 封装

只用一个库、三个 store，不引第三方库：

```js
const request = indexedDB.open("pick-local", 1);
request.onupgradeneeded = () => {
  const db = request.result;
  const photos = db.createObjectStore("photos", { keyPath: "key" });
  photos.createIndex("session", "session");
  db.createObjectStore("selections", { keyPath: "session" });
  const shares = db.createObjectStore("shares", { keyPath: "token" });
  shares.createIndex("session", "session");
};
```

写操作包一层 Promise，事务 `oncomplete` 才算成功：

```js
await dbPut("photos", { key, session, name, mime, size: blob.size, blob, createdAt });
```

配额异常时返回明确错误，而不是静默失败：

```js
if (err.name === "QuotaExceededError") return jsonResponse({ error: "本机浏览器存储空间不足" }, 507);
```

## 3. 图片怎么显示：Service Worker

页面里是 `<img src="/img/<key>">`，浏览器会走网络请求，而服务器上没有这些图。三种解法：

| 方案 | 问题 |
|---|---|
| 把 Blob 转 objectURL 塞回 DOM | 页面用 `innerHTML` 批量渲染，拿不到每张图的时机，容易闪裂图 |
| 拦截 `HTMLImageElement.src` setter | `innerHTML` 解析时走的是 attribute，不经过 setter |
| **Service Worker 拦截 `/img/`** | 干净、对页面零侵入 ✅ |

```js
self.addEventListener("fetch", (event) => {
  const url = new URL(event.request.url);
  if (url.origin !== self.location.origin) return;
  if (!url.pathname.startsWith("/img/")) return;
  const key = decodeURIComponent(url.pathname.slice(5));
  event.respondWith(fromIndexedDb(key));   // 返回 Response(blob)
});
```

注册时要处理"首次访问还没接管"的窗口：

```js
navigator.serviceWorker.register("/sw.js")
  .then(() => navigator.serviceWorker.ready)
  .then(() => {
    if (!navigator.serviceWorker.controller && !sessionStorage.getItem("pick.sw.reload")) {
      sessionStorage.setItem("pick.sw.reload", "1");
      location.reload();          // 只重载一次，防止死循环
    }
  });
```

注意：SW 必须从根路径注册（`/sw.js`），才能拦截 `/img/`；否则 scope 不够。

## 4. 存储统计

`navigator.storage.estimate()` 给出本机配额，用于进度条：

```js
const { usage, quota } = await navigator.storage.estimate();
```

界面上显示"照片数据约 X / 本机配额 Y"，接近 90% 变红提示清理。注意统计的是**整个站点**占用，包含索引与选片记录，所以照片字节数只是下限。

## 5. 性能与体验细节

1. 网格图 `loading="lazy"`，一页 20 张时首屏只解码可视区域
2. 大图每次切换创建新的 `Image` 对象，旧图先移除 `src`，避免慢请求覆盖新图
3. 大图预加载前后各一张，翻页更顺
4. 20 秒加载超时 + "重新加载"按钮，弱网下不至于卡死
5. `beforeunload` 在上传中提示，防止误关
