# 05 · 选片交互与分享链接

> 目标：把"勾选"这件小事做到不出错，并让模特在手机上三步完成交付。

## 1. 前端状态模型

```js
const state = {
  photos: [],          // 当前场次的 key 列表，稳定排序
  selected: new Set(), // 已选文件名
  savedStatus: "draft",
  dirty: false,        // 有未保存修改
  filter: "all",       // all | picked | unpicked
  page: 1, pageSize: 20,
  quick: true,         // 快速模式
  lbIdx: -1            // 大图索引
};
```

三条铁律：

1. `selected` 存**文件名**，不存索引——筛选、分页、重排都不会错位
2. 任何勾选变化立刻 `dirty = true`，界面徽标变"未保存"
3. 保存成功才清 `dirty`；失败保留勾选，只提示"保存未完成，请重试"

## 2. 看图的两种模式

| 模式 | 点照片 | 点 `＋` | 点 🔍 |
|---|---|---|---|
| 快速模式（默认） | 直接勾选 | 勾选 | 看大图 |
| 浏览模式 | 看大图 | 勾选 | 看大图 |

大图里：`←/→` 切换、`空格` 选/取消、`Esc` 关闭；底部按钮同时是状态显示（"选这张" / "已选（点此取消）"）。

## 3. 保存：草稿与确认

```js
await fetch("/api/selection", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ session, filenames: [...selected], status }) // draft | confirmed
});
```

- 草稿可反复覆盖
- 确认时后端再校验一次"不能为空"
- 保存带 20 秒超时；超时不改本地状态，提示重试
- 模特端同样逻辑，进度按链接 token 归属，换手机打开同一链接也能恢复

## 4. 分享链接

### 4.1 token 即身份

```js
const token = crypto.randomBytes(16).toString("hex");   // 32 位十六进制
```

- 一条链接绑定一个场次，网页里所有接口都从 URL 取 token
- 不做登录、不发 Cookie，方便直接发微信
- token 等于密码，不要发公开群；删除链接时连带删除该链接的选片记录

### 4.2 发布流程

1. `POST /api/shares { session, permanent }` 拿到 token
2. 逐张 `PUT /api/shares/:token/photos?name=<文件名>`（并发 3，单张 ≤1MB）
3. 本地 `shares` 表记一条账（token、场次、过期时间）
4. 返回 `/m/<token>`，页面拼成完整 URL 供复制

任一步失败 → 删除刚建的服务端链接 → 报错。**不留半条链接**，否则用户会发出一堆打不开的地址。

### 4.3 有效期与失效

- 默认 30 天，可勾"永久有效"
- 管理页列出本地账本里的每条链接，并**实时探测**服务端是否还在：
  - 链接不存在 → 标"已失效"
  - 过期 → 标"已失效"
  - 正常 → 显示到期日或"永久有效"
- 服务端实例重启会清空快照：链接会显示"已失效"，重新生成即可；本地照片与勾选不受影响

## 5. 模特端

页面只有一个入口：`GET /m/<token>`。服务端先校验 token，通过才返回 `model.html`。

模特页的接口适配只有三个：

```js
"/api/photos"    → "/api/shares/<token>/photos"
"/img/<key>"     → "/api/shares/<token>/img/<文件名>"
"/api/selection" → "/api/shares/<token>/selection"
```

注意 `src` 必须用绝对路径（`/model-api.js`）。相对路径在 `/m/<token>` 下会被解析成 `/m/model-api.js`，直接 404——这个坑真实发生过，详见 [07-踩坑与排查](07-踩坑与排查.md)。

## 6. 结果汇总

管理页"选片结果"把两个来源合并：

1. 本机管理员自己的勾选（token 记为 `admin`）
2. 该场次每条链接在服务端的提交

按 `updated_at` 倒序展示，标注"已确认/草稿"和提交时间；"复制全部文件名"会跨链接去重并按自然序排序。

## 7. 提交通知

每 15 秒轮询一次，页面不可见时暂停：

```js
GET /api/notifications?since=<上次服务器时间或 30 分钟前>
→ { serverTime, since, items: [{ token, session, count, updated_at }] }
```

- 只在"确认"状态下通知，草稿不打扰
- 卡片 60 秒自动消失，最多同时 4 条
- 点击卡片 = 切到该场次 + 打开结果面板
- 用 `token|session|updated_at` 做去重键，刷新页面不会重复弹

## 8. AI 整理提示词

摄影师拿到清单后，还要把未选的 RAW 挪走。结果面板可以一键复制一段结构化指令，粘贴给任意能操作网盘的 AI：

- 目标：`场次/00-未选/`
- 规则：按主名比对、`-2/-3` 调色副本回退基础名、命中清单的留在原地
- 步骤：先报未选数量与前 20 个文件名，等人工确认后再分批移动（每批 ≤100）
- 硬约束：不删、不覆盖、不改名、只在本场目录内操作

这样"选片"和"归档"之间不用再手工拼清单。
