# 06 · 部署上线

> 目标：让模板跑在公网上，并知道"什么时候该换方案"。

## 1. 部署前检查

模板是一个**单进程 Node 20 服务**，满足：

- 零第三方依赖（`package.json` 没有 dependencies，不用 `npm install`）
- 读取 `process.env.PORT`，并绑定 `0.0.0.0`
- 启动后常驻前台，不 daemonize
- 运行时只写 `${TMPDIR:-/tmp}`，且自动 `mkdir -p`

```bash
PORT=8000 node server.js     # 本地模拟生产
```

## 2. 需要准备的两个脚本

不同平台细节不同，但契约一样：

`build.sh`

```sh
#!/bin/sh
set -eu

mkdir -p dist/public
cp server.js run.sh package.json dist/
cp public/index.html public/model.html public/auth.js public/local-api.js public/model-api.js public/sw.js dist/public/
chmod 755 dist/run.sh
```

`run.sh`

```sh
#!/bin/sh
set -eu

exec node server.js
```

要点：

- 必须是 POSIX `sh`，不要用 bash 数组/`[[ ]]`
- `run.sh` 必须被复制进产物目录并保留可执行位
- 静态文件要跟着 `server.js` 一起进产物，否则线上 404

## 3. 部署到 Trae 部署平台（本仓库线上示例用的方式）

平台概念：Site（站点）→ Deployment（一次部署）→ 运行 Node 20 实例。

执行配置 `execution.json`：

```json
{
  "schema_version": 1,
  "build": {
    "runtime_key": "nodejs20",
    "build_script": "build.sh",
    "output_dir": "dist",
    "environment": {},
    "timeout_seconds": 600
  },
  "runtime": {
    "runtime_key": "nodejs20",
    "start_script": "run.sh",
    "port": 8000,
    "environment": {}
  }
}
```

流程：

```bash
# 1. 查看已有站点，避免把新应用部署到别人的 Site
trae-deploy sites list

# 2. 新建站点（描述写清源码位置与用途，方便下次复用）
trae-deploy sites create --name "摄影选片工作台" --description "..." 

# 3. 设置访问权限（private 仅自己 / public 所有人）
trae-deploy sites update-config --site-id <id> --access-policy public

# 4. 部署
trae-deploy deployments create \
  --site-id <id> \
  --title "首次部署" \
  --description "..." \
  --type function-web \
  --source-dir <准备目录> \
  --execution-config <准备目录>/execution.json \
  --app-tags 123,267

# 5. 等待终态
trae-deploy deployments wait --deployment-id <dep-id>
```

注意事项：

- 打包目录要排除 `node_modules`、`.git`、日志、`.env`
- 部署成功后平台会给出 `https://<前缀>.<平台域名>` 的地址
- 域名**前缀可自定义**（`sites update-domain --domain-prefix`），后缀固定；带点的多级前缀不支持
- 改前缀 = 换 origin：浏览器本地库、密码、已发链接都要重建

## 4. 其它部署方式

| 平台 | 做法 | 注意 |
|---|---|---|
| 任意 VPS | `node server.js` + systemd/pm2 + Nginx 反代 | 必须配 HTTPS，否则 Service Worker 不生效 |
| Docker | `FROM node:20-alpine`，复制 `server.js` 与 `public/` | 容器重启会丢快照，属预期 |
| 云函数/容器平台 | 按"单端口 HTTP 服务"上传 | 多实例部署时内存快照不共享，链接会随机失效 |
| Cloudflare Workers + D1 | 换用原版实现 | 需要建库、绑自定义域，见文末 |

**多实例是最容易忽略的坑**：服务端快照存在进程内存，请求被负载均衡到另一台机器就 404。要么平台保证单实例，要么把快照换成共享存储。

## 5. 上线后验收

- [ ] 首页返回 200，出现设置密码卡片
- [ ] 设置密码后进入工作台，刷新仍登录
- [ ] 上传照片，网格正常显示（验证 Service Worker）
- [ ] 生成链接，手机（不同网络）能打开并看到照片
- [ ] 模特提交，管理页收到通知
- [ ] 删除链接后，模特页提示链接无效
- [ ] 手机 375px 宽度无横向滚动
- [ ] 断网重开，已加载过的照片仍能显示

## 6. 运维与成本

- **内存**：快照全在内存，单实例建议 ≤200MB 照片；超过就只在需要时上传少量场次
- **配额**：浏览器侧受本机配额限制；服务端侧可加 `MAX_TOTAL_BYTES` 兜底
- **日志**：至少记录启动端口、快照恢复数量、上传失败原因；不要打印 token
- **备份**：本机照片库没有云端备份，重要场次建议保留原始导出目录

## 7. 想做成长期可用的服务

把"临时快照"换成"持久存储"即可，UI 不用动：

1. `server.js` 里 `Map` → 数据库表（SQLite/Postgres）
2. 图片 `buf` → 对象存储（S3/R2/OSS），库里存 URL
3. 增加管理员账号体系（哈希入库、签名 Cookie）
4. 增加定时清理过期链接与孤儿图片

原版 Cloudflare Workers + D1 就是这套思路的完整实现：<https://github.com/Pandaemonium-Lujiu/photoshoot-picker>
