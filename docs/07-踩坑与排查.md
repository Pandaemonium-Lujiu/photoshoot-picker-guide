# 07 · 踩坑与排查

> 这里每一条都是真实踩过的坑，按"现象 → 原因 → 修法"记录，遇到问题先搜现象。

## 1. 模特链接刚生成就提示"已过期"

**现象**：管理页生成了链接，点开显示"链接无效或已过期，请联系摄影师重新获取"。

**原因**：模特页里写的是相对路径 `<script src="model-api.js">`。页面地址是 `/m/<token>`，浏览器按目录解析成 `/m/model-api.js` → 404；适配层没加载，页面请求直接打到服务器不存在的老接口 → 404 → 页面按"链接失效"处理。

**修法**：

- 所有静态引用用绝对路径：`/model-api.js`、`/auth.js`、`/local-api.js`、`/sw.js`
- token 解析兼容结尾斜杠：

```js
const TOKEN = decodeURIComponent(location.pathname.slice(3)).replace(/\/+$/, "");
```

**教训**：部署在子路径下的页面，任何相对资源路径都要重新算一遍。

## 2. 部署/重启后所有链接失效

**现象**：重新部署一次，之前发出去的链接全打不开。

**原因**：快照存在 Node 进程内存（+ 临时磁盘），新实例没有旧数据。

**修法**：重新生成链接。要根治只有换持久存储（见 [06-部署上线](06-部署上线.md#7-想做成长期可用的服务)）。

**产品层应对**：界面上明确写"服务重启后可能失效，重新生成即可"，并把失效链接标灰，避免模特反复来问。

## 3. 多实例时链接"时好时坏"

**现象**：同一个链接刷新几次，有时正常、有时 404。

**原因**：平台按并发自动扩缩容，请求被路由到没有该快照的实例。

**修法**：

- 优先选单实例部署；上传并发降到 1–3，减少扩容概率
- 或把快照放共享存储（数据库/对象存储）
- 排查方法：给服务加一个 `/api/health` 返回实例 ID 与快照数，观察是否出现不同实例

## 4. 换域名后"照片全没了"

**现象**：改了站点前缀，打开新域名是空库，还要重新设密码。

**原因**：IndexedDB 与 localStorage 按 **origin** 隔离，换域名等于换一个存储空间。

**修法**：正式启用前把域名定下来；必须迁移时只能重新上传（或写一次性导出/导入脚本）。

## 5. 图片在网格里破图，但接口有数据

**现象**：`<img src="/img/场次/a.jpg">` 请求 404，照片明明已存进 IndexedDB。

**原因**：`<img>` 的网络请求不经过 `window.fetch` 拦截，必须靠 Service Worker。

**修法**：见 [04-照片上传与本地库](04-照片上传与本地库.md#3-图片怎么显示service-worker)。同时处理首次访问 SW 还没接管的情况（注册 → `ready` → 若无 `controller` 则重载一次，用 `sessionStorage` 防止循环）。

## 6. 已选清单不显示 / 底部翻页条空白占位

**现象**：勾选后"已选清单"区域不出现；没有照片时底部还留着一条空白分页框。

**原因**：

- 清单渲染被一个永远为假的开关拦住（早期版本遗留 `if (!el.dataset.open) return`）
- 分页条的隐藏样式只写了 `#pager[hidden]`，而底部那条是 `.pager.bottom-pager`，选择器没命中

**修法**：

```css
.pager[hidden]{display:none}     /* 用 class，而不是 id */
```

```js
// 渲染前不再看 dataset 开关
$("#pkList").innerHTML = list.map(...).join("");
```

## 7. 文件名里带引号/尖括号，界面崩了

**现象**：某个文件名包含 `'` 或 `<`，勾选后整块列表错乱，甚至执行了意外脚本。

**原因**：直接把文件名拼进 `innerHTML`。

**修法**：统一转义后再拼：

```js
const esc = v => String(v).replace(/[&<>"']/g, c => (
  {"&":"&amp;","<":"&lt;",">":"&gt;",'"':"&quot;","'":"&#39;"}[c]
));
```

## 8. 文件名被"二次解码"报错

**现象**：上传含 `%` 的文件名时报 `URIError: URI malformed`。

**原因**：`URLSearchParams.get()` 已经解码过一次，代码里又 `decodeURIComponent` 了一次。

**修法**：查询参数只解码一次；只有 `location.pathname` 这种原始路径才需要手动 `decodeURIComponent`。

## 9. 上传成功但网格不刷新

**现象**：状态栏显示"新增 12 张"，网格还是旧的。

**原因**：图片 URL 没变，浏览器/Service Worker 用了缓存；或上传后没有重新拉列表。

**修法**：

- 上传完成后统一 `loadPhotos()` 重拉
- 覆盖同名图时给图片 URL 加版本参数（`?_v=<时间戳>`）
- Service Worker 对 `/img/` 返回 `Cache-Control: no-store`

## 10. 密码忘了怎么办

**事实**：服务端没有账号体系，密码哈希只在本机，**无法找回**。

**处置**：

1. 浏览器开发者工具 → Application → 清除该站点的 localStorage（只清 `pick.auth.*`）
2. 刷新页面，重新设置密码
3. IndexedDB 里的照片与选片记录仍在

**预防**：UI 上写明"忘记密码无法找回"；重要设备上不要把密码存在浏览器密码管理器之外的地方。

## 11. 平台/框架相关

| 现象 | 原因 | 修法 |
|---|---|---|
| `ERR_UNKNOWN_BUILTIN_MODULE: node:sqlite` | `node:sqlite` 是 Node 22+，Node 20 没有 | 用文件/数据库服务，别用该内置模块 |
| 启动日志显示监听 3000，健康检查 8000 失败 | 端口写死 | 读 `process.env.PORT`，并让配置端口与之一致 |
| `MODULE_NOT_FOUND` | 依赖没被放进产物目录 | 零依赖最省心；有依赖要把 `node_modules` 复制进产物 |
| 静态页 200 但接口 404 | 路由只处理了 `/`，没处理 `/api/*` | 在服务端显式列白名单，别用"相对路径猜测" |
| 图片/HTML 被 CDN 缓存旧版本 | 缓存头不当 | HTML 与 SW 用 `no-store`，图片用短缓存 |

## 12. 通用排查顺序

1. **打开 DevTools → Network**：看失败请求的完整 URL、状态码、响应体
2. **看 Console**：脚本 404、`URIError`、CORS、SW 报错都会在这里
3. **Application → Service Workers**：是否 activated、是否 controlling 当前页
4. **Application → IndexedDB**：照片记录是否存在、`size` 是否正常
5. **Application → Local Storage**：`pick.auth.v1`、`pick.session`、`pick.notifySince`
6. **服务端日志**：启动端口、快照数、上传失败原因
7. 仍无法定位时，先用 `curl` 直接打接口，区分"前端问题"还是"服务端问题"

## 13. 一条经验

凡是"本地好的、线上坏的"，优先怀疑三件事：**路径、缓存、状态存在哪**。
