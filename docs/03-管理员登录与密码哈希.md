# 03 · 管理员登录与密码哈希

> 目标：没有后端账号体系，也要做到"打开就要密码、密码不落地明文、改密码旧密码立即失效"。

## 1. 设计决策

| 问题 | 结论 | 原因 |
|---|---|---|
| 密码存哪 | 本机 `localStorage` | 照片本来就在本机，密码没有跨设备意义 |
| 存什么 | PBKDF2-SHA256 加盐哈希 | 数据库泄露时无法反推密码 |
| 传服务器吗 | 不传 | 服务端不需要知道管理员是谁 |
| 登录态 | 本机时间戳，30 天 | 避免每次刷新都输密码 |
| 忘记密码 | 不可找回，只能清站点数据重设 | 无邮箱/短信通道；照片仍在本机 |

如果做成 A 方案（服务端数据库），密码哈希应存服务端，登录态用 `HttpOnly` 签名 Cookie——那是另一种实现，别混用。

## 2. 首次设置 / 登录 / 改密码

```js
const AUTH_KEY = "pick.auth.v1";
const SESSION_KEY = "pick.auth.session";
const ITERATIONS = 150000;

async function hashPassword(password, saltB64, iterations) {
  const key = await crypto.subtle.importKey(
    "raw", new TextEncoder().encode(password), "PBKDF2", false, ["deriveBits"]
  );
  const bits = await crypto.subtle.deriveBits(
    { name: "PBKDF2", hash: "SHA-256", salt: fromB64url(saltB64), iterations },
    key, 256
  );
  return toB64url(new Uint8Array(bits));
}

async function writeAuth(password) {
  const salt = toB64url(crypto.getRandomValues(new Uint8Array(16)));
  const hash = await hashPassword(password, salt, ITERATIONS);
  localStorage.setItem(AUTH_KEY, JSON.stringify({
    v: 1, alg: "PBKDF2-SHA256", iter: ITERATIONS, salt, hash,
    createdAt: new Date().toISOString()
  }));
}
```

要点：

1. **每个用户独立盐**，16 字节随机；盐不需要保密，和哈希一起存
2. **迭代次数写进记录**，以后提高强度不会让老密码失效
3. **比较用常量时间**：先各自 SHA-256，再逐字节异或累加，避免字符比较提前返回
4. 首次进入判断"有没有记录"：没有 → 设置密码（两次输入、≥8 位）；有 → 验证

## 3. 登录态

```js
function openSession() {
  localStorage.setItem(SESSION_KEY, JSON.stringify({ expires: Date.now() + 30 * 86400000 }));
}
function sessionValid() {
  const data = JSON.parse(localStorage.getItem(SESSION_KEY) || "null");
  return !!data && Number(data.expires) > Date.now();
}
```

这只是 UX 层：真正保护数据的是"照片只存本机"。任何人清掉 `localStorage` 都能重新设置密码——但拿不到你的照片（除非他也能访问你的浏览器数据）。这一点必须在文档和 UI 里说清楚，不要宣称"服务端加密保护"。

## 4. 修改密码

`local-api.js` 拦截 `/api/password`：

```js
if (!(await window.PickAuth.verifyPassword(body.current || ""))) {
  return jsonResponse({ error: "当前密码不正确" }, 401);
}
if (typeof body.password !== "string" || body.password.length < 8) {
  return jsonResponse({ error: "新密码须为 8 至 512 个字符" }, 400);
}
await window.PickAuth.writeAuth(body.password);
return jsonResponse({ ok: true });
```

修改后不需要强制登出：当前浏览器已通过验证，保留登录态；其他设备本来就没有这个站点的数据。

## 5. 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 明文密码存 `localStorage` | 任何人打开 DevTools 都能看到 | 只存 PBKDF2 哈希 |
| 把哈希 POST 给服务器 | 多一个泄露面，且服务端并不需要 | 本地校验 |
| 用 `===` 直接比较哈希 | 理论上的时序侧信道 | 常量时间比较 |
| 全局固定盐 | 彩虹表成本降低 | 每条记录随机盐 |
| 忘记"迭代次数要做版本化" | 以后无法平滑升级参数 | 把 `iter`/`alg` 写进记录 |
| 密码提示语泄露信息 | 社工风险 | 只说"密码不正确" |
